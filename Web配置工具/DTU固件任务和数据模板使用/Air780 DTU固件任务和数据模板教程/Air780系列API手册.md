# 二、API使用方法

​      参考demo使用。提到的硬件资源ID，比如串口ID，ADCID和输入输出ID，需要根据具体硬件二次开发手册确定。不同的硬件，功能不同，支持的API也不一样。比如GPS的只有Air780EG系列支持，继电器输出的只有带继电器的设备支持，ADC的只有带ADC采集的设备支持。

​    注意Air724系列和Air780系列 API不一样，不兼容，不能混用。

# 四、网络相关API

| 编号   | 项目                                                         | 描述                                |
| ------ | ------------------------------------------------------------ | ----------------------------------- |
| 1      | API                                                          | PronetStopProRecCh(on)              |
| 功能   | 停止DTU内部处理网络接收数据（所有的网络通道，数据都会被截取） |                                     |
| 参数   | on：1 表示停止，0表示启用（不是网络通道id，只有0和1两个参数） |                                     |
| 返回值 | 无                                                           |                                     |
| 说明   | 任务要处理网络数据，必须调用，否则读取不到数据，停止内部处理接收的网络数据，可以用任务读取缓存，截取接收到的数据自己处理逻辑 |                                     |
| 2      | API                                                          | PronetGetRecChAndDel(id)            |
| 功能   | 读取DTU内部网络接收数据缓存                                  |                                     |
| 参数   | id:是网络通道ID，1~n                                         |                                     |
| 返回值 | nil:表示无数据；其他:字符串格式,有效数据                     |                                     |
| 说明   | 注意:循环获取，直到返回nil，可以清除内部接收缓存             |                                     |
| 3      | API                                                          | PronetGetNetSta(id)                 |
| 功能   | 获取网络通道状态                                             |                                     |
| 参数   | id：网络通道，1~n                                            |                                     |
| 返回值 | nil:表示没有这个网络通道；0: 表示连接失败；1: 表示连接成功； |                                     |
| 说明   | 在发送数据之前，可以先判断网络是否正常，如果正常就调用PronetSetSendCh发送，如果不正常可以丢弃，也可以保存，或者其他逻辑 |                                     |
| 4      | API                                                          | PronetSetSendCh(id,s)               |
| 功能   | 调用网络通道发送数据                                         |                                     |
| 参数   | id 网络通道,1-ns 需要发送的数据(tcp,udp，http必须是字符串否则会报错mqtt协议可以字符串，可以是table类型，如果是table类型，格式固定。s[1] 是字符串的topic名字或者整形的topic发布编号,s[2] 是需要发布的字符串数据) |                                     |
| 返回值 | 无                                                           |                                     |
| 说明   | MQTT协议发送的时候数据的时候，指定topic编号方法是:local s={}s[1]=1s[2]="need send data"PronetSetSendCh(id,s)指定自定义topic名称方法是:local s={}s[1]="send topic name"s[2]="need send data"PronetSetSendCh(id,s) |                                     |
| 5      | API                                                          | PronetMqttProReciveTopic(nid,s,seg) |
| 功能   | MQTT 通道协议特殊函数,设置接收数据里面是否包含topic名称      |                                     |
| 参数   | nid： 网络通道ID 1-ns：1,添加topic名字，0不添加seg：字符串类型,topic 和数据之间的分隔符 |                                     |
| 返回值 | 无                                                           |                                     |
| 说明   | 只需要设置一次，如果设置了后 topic名称，网络收到数据后，串口传出的数据是 topic名字+seg分隔符+数据 |                                     |

# 五、串口相关API

| 编号   | 项目                                                         | 描述                   |
| ------ | ------------------------------------------------------------ | ---------------------- |
| 1      | API                                                          | UartStopProRecCh(on)   |
| 功能   | 停止DTU内部处理串口接收数据（所有的串口通道，数据都会被截取） |                        |
| 参数   | 参数:on：1 表示停止，0表示启用（不是串口号，只有0和1两个参数，比如三个串口的设备不是UartStopProRecCh(1)，UartStopProRecCh(2)，UartStopProRecCh(3)，只需要单独调用一次UartStopProRecCh(1)就会截取所有串口通道的数据，然后使用UartGetRecChAndDel(id)去获取不同串口通道的数据） |                        |
| 返回值 | 无                                                           |                        |
| 说明   | 任务要处理串口数据，必须调用，否则读取不到数据，停止内部处理接收的串口数据，可以用任务读取缓存，截取接收到的数据自己处理逻辑 |                        |
| 2      | API                                                          | UartGetRecChAndDel(id) |
| 功能   | 获取串口缓存数据                                             |                        |
| 参数   | id是串口编号范围1,2,3，对应的硬件类型，可以查对应硬件规格书， 找技术支持发资料 |                        |
| 返回值 | nil：表示无数据其他:字符串格式,有效数据                      |                        |
| 说明   | 串口接收的包是否完整，和串口分包超时时间有关系，如果数据量大可以适当调整其大小，比如300；循环获取，直到返回nil，可以清除内部接收缓存； |                        |
| 3      | API                                                          | UartSetSendCh(id,s)    |
| 功能   | 调用串口对外发送数据                                         |                        |
| 参数   | id:是串口编号范围1,2,3，对应的硬件类型，可以查对应硬件规格书s：是需要发送的字符串，类型为string |                        |
| 返回值 | 无                                                           |                        |
| 说明   | RS485发送数据的时候，可能会导致乱码，需要调整RS485 的EN反转时间如果发现有乱码，可以设置5000~20000后在试试。 |                        |

# 十三、工具API

注意:工具API只是一个补充方便使用的一个经验函数，不表示效率高。主要用来处理hex数据的。

完全可以用原厂的API实现相同功能。

| 编号   | 项目                                                         | 描述                           |
| ------ | ------------------------------------------------------------ | ------------------------------ |
| 1      | API                                                          | ToolHexStrToTable(s)           |
| 功能   | hex 字符串转换成table                                        |                                |
| 参数   | hex的字符串，如0x00 0x01 0xaa                                |                                |
| 返回值 | 返回:nil 或者table                                           |                                |
| 说明   | 专门处理16进制的hex数据，转换成table，然后可以用下标的方式引用数据，下标从1开始。比如输入数据是0x00 0x01 0xaa。返回的数据是t,t[1]=0x00,t[2]=0x01 |                                |
| 2      | API                                                          | ToolTableToHexStr(t)           |
| 功能   | 把table 转换成 hex sting                                     |                                |
| 参数   | 需要转换的table                                              |                                |
| 返回值 | hex字符串                                                    |                                |

# 十四、时间类API

关于时间，调用config,get,nettime命令获取的时间并不一定可靠。这个时间来源于基站时间或者网络时间。

网络时间基于网络，如果没网络时间肯定不对，有的基站本身时间就是错误的；NTP也可能刚开始同步失败，导致模块时间错误。如果您的设备要时间很严格；可以做业务逻辑实现，让自己的服务器与设备之间同步时间。
