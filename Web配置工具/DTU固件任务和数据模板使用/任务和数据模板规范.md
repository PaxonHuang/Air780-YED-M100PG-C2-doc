# 一、简介

​       任务和数据模板是基于银尔达成熟稳定的DTU固件架构和平台，做固件微开发，实现数据转换，业务动态修改，自定义业务逻辑的一种方便方法。通过DTU的配置平台，配置一段动态可执行的代码到DTU内部，设备可以自动执行这部分代码，实现网络数据和串口数据的收/发/解析/计算/转换。实现GPIO/继电器的控制；实现ADC数据的采集等功能，自由度高，灵活性强。常见的使用场景：

​    1、设备与服务器之间进行数据格式转换，比如mobus与json转；

​    2、自定义设备控制逻辑，任务截取收到的数据，然后转换成自定义逻辑；

​    3、数据加密解密；

​    4、边沿计算，自动采集从机设备，按需上报和本地联动控制。

# 二、任务与数据模板的区别

​     任务是一个协程/线程，独立运行的一个程序，一直在循环运行,里面要用while保持程序一直运行。

​     数据模板是一个代码片，一次性的，每次有串口或者网络数据后，对应的模板执行一次，执行一次后就结束释放了，下次触发重新执行。

​     数据模板一般用于数据格式处理，比如hex转json，或者数据过滤等简单逻辑。

​     任务可以包含数据模板的功能，并且可以做边缘计算，数据统计，逻辑自定义等复杂功能。

# 三、使用注意事项

1、在编辑的时候，注意先在文档里面编辑，然后一次性拷贝到浏览器里面，不要在浏览器里面编辑

2、开始的function 和最后的end 是固定格式，function前面和end后面不能有空格

2、整个配置文件最大50KB,如果过于复杂，可以考虑固件定制

3、需要懂lua 语言语法

4、程序逻辑要健壮，如果异常会导致整个设备崩溃重启

5、Air724系列用的是lua 5.1版本，Air780系列用的是lua 5.3 不同版本支持的系统api不一样，不兼容。



# 四、数据模板格式

注意:数据模板里面不能调用sys.wait延迟。

下面是发送模板，格式是固的以function开头   end结尾   中间是一串可执行的lua代码， ...是串口的数据数据，处理完return 的数据是需要发送给服务器的

```lua
function
	local str=...
	log.info("send prot")
	return "send prot"..str
end
```



下面是接收数据流模板，以function开头   end结尾   中间是一串可执行的lua代码， ...是服务器下发的数据数据，处理完return 的数据是需要发送给串口的



```lua
function
	local str=...
	log.info("recive prot")
	return "recive prot"..str
end
```

 

# 五、任务格式

​    任务与数据模板的区别是任务是一直循环执行的。数据模板能做的事情任务都能做，下面是任务模板，以function开头   end结尾   中间是一串可执行的lua 协程，里面可以调用lua开发的API程序，一定要有延迟，否则会一直占用CPU。

注意:

任务里面要保证任何时候都不能有死循环(需要有sys.wait释放CPU)。

任务里面可以封装自己的函数，叫lua 闭包函数。但是所有的定义都必须写到funciton    end 内部。

任务里面不能调用require函数引用库。

任务里面可以有注释，但是最好不要写过多注释，会影响最大脚本容量。

```lua
function
  local function axxx()
    log.info("axxxx")
  end 
  
	while 1 do 
		log.info("sys task prot")
    axxx()
		sys.wait(1000)
	end 
end
```

# 七、异常恢复

​    1、当数据目标或者任务错误后，可能会导致模块持续崩溃重启。air724系列，固件小于1.3.0系列必须重新烧录固件，固件大于1.3.0，先删除异常的任务保存参数，然后一直按住Reload按键，再上电设备，维持按键7秒以上，设备会恢复出厂设置，恢复错误。

​    2、Air780的内存比较小，只能做简单的数据转换，如果比较复杂，使用Air724系列DTU（内存大）

​    3、Air780的的API与Air724的API不兼容，不能混用。
