根据不同的产品型号，支持的功能不通，UI看到的界面有差异，以实际设备看到UI为准。比如YED-RY1440有输入输出，就能看到GPIO界面。YED-Core-Air724没有GPIO输入输出，就看不到GPIP界面。

不同的固件版本，对UI显示的功能支持情况不一样，如果配置参数后无效，升级最新DTU固件。

随着固件功能功能的升级，UI可能变化。

# 四、自动轮询

自动轮询，是提前在DTU内保存对外轮询的命令，当设置命令后，DTU就会按照间隔自动发送数据给串口。当收到串口数据后，在自动发送到服务器，这样可以减少服务器的轮询流量，适合一个设备一条命令，或者返回的数据能区分长度和设备的场景。如果有很多设备，并且无法区分返回数据归属的情况下，一般用任务去实现，可以自由解析处理数据。

| 参数项目         | 参数说明                                                     |
| ---------------- | ------------------------------------------------------------ |
| 是否启动         | 启动后，就会发送对应的数据                                   |
| 轮询应答超时时间 | 当发送一条命令后，等待这个时间发送下一跳轮询命令。两条命令之间间隔 |
| 轮询周期时间     | 当设置的全部命令轮询完成后，等待这个时间后，继续从第一条命令开始轮询 |
| 轮询命令格式     | 轮询的数据格式，可以是字符串或者Hex16进制。DTU会根据类型转数据 |
| 轮询命令         | 需要发送的命令当设置字符串的时候，轮询原封不动的发送出去，设置Hex 16进制格式的时候，比如要设置0xaa 0x01 0xbb ，设置格式为 aa 01 bb或者aa01bb大部分场景的命令是modbus命令 |

# 五、网络通道参数

# 九、定位

定位分基站定位，WIFI 定位，GPS定位和。

基站定位偏差大500~几公里，可以在室内定位。

基站定位周期最小60秒。



WIFI定位在50~200米，可以室内定位，附近必须要附近有WIFI。

WIFI和基站定位同时存在的时候，以WIFI定位优先，如果WIFI定位失败会用基站定位数据定位。

WIFI和基站信息都在定位服务器数据库内才能定位，否则也定不了位。

WIFI和基站定位必须在大陆才能有用。



GPS定位准去，必须在室外空旷的地方定位。

GPS定位周期最小60秒。

定位信息可以自动上报，但是可能和串口数据同时到达服务器，导致冲突。这一般可以用任务处理做成。任何可以灵活的组装和拼接各种数据格式。

| 参数项目         | 参数说明                                                     | 备注 |
| ---------------- | ------------------------------------------------------------ | ---- |
| 是否启动         | 是否启动，注意启动后数据                                     |      |
| 更新时间         | 定位间隔时间。周期定位，基站/WIFI定位需要消耗流量，大约1K一次。 |      |
| 主动上报内容格式 | 定位成功后，到达上报时间后，上报数据，可以使用变量。不支持原始数据。 |      |
| 主动上报通道     | 定位成功后，到达上报时间后，上报数据                         |      |

# 十、短信转发

Air780支持，Air724不支持。

使用手机卡，可以接受短信，并且把接收到的短信转发到目标服务器。

需要提前打开这个功能，串口才能获取和发送短信，如果不需要上报就不上报。

开启后，任务里面可以调用发送短信的API。

| 参数项目     | 参数说明                                                     | 备注 |
| ------------ | ------------------------------------------------------------ | ---- |
| 是否启动     | 是否启动                                                     |      |
| 是否过滤     | 是否过滤接收的短信号码，如果过滤了只有被允许的号码才能转发。 |      |
| 允许号码     |                                                              |      |
| 短信上报格式 | 固定格式和自定义格式，指定一个可以使用变量                   |      |
| 短信上报内容 | 字符串格式支持变量Air780EPM方案固件版本大于等于V2.0.4版本，这个地方也支持标准的变量比如${IMEI},${ICCID} |      |
| 上报通道     |                                                              |      |
| 内部缓存     | 只有打开了缓存，任务可以获取并处理收到的短信。串口也可以获取短信 |      |

# 十二、固件升级

V1.1.12版本及其以上固件支持。固件升级是DTU下载设备需要的升级固件，然后分包传送设备，不是说的DTU自身的固件升级。

使用的时候需要串口配合upcheck和upin命令，具体参看:https://yinerda.yuque.com/yt1fh6/4gdtu/py7g1e2x5rh7tma1#

获取固件文件有2种方式，一种是自建服务器，支持断点续传。只需要配置文件下载的url即可。

一种是使用银尔达文件服务器，上传文件服务器后，会得到一个文件ID，把文件ID配置进去即可。

![img](https://cdn.nlark.com/yuque/0/2024/png/804193/1726047301614-18f6a7f4-3b8c-4d48-9662-9e150de14990.png?x-oss-process=image%2Fwatermark%2Ctype_d3F5LW1pY3JvaGVp%2Csize_50%2Ctext_eWluZXJkYQ%3D%3D%2Ccolor_FFFFFF%2Cshadow_50%2Ct_80%2Cg_se%2Cx_10%2Cy_10)

| 参数项目     | 参数说明                                                     | 备注 |
| ------------ | ------------------------------------------------------------ | ---- |
| 是否启动     | 如果启用了，参数需要配置正确                                 |      |
| 文件版本号   | 自定义的版本号，MCU主板可以发upcheck命令 获取到返回一般用于与自身固件配合决定是否升级。 |      |
| 文件获取方式 | 文件ID: 银尔达文件服务器下载url :自建服务器使用              |      |
| 文件下载路径 | 如果获取方式是文件ID: 填写银尔达文件管理里面的文件ID如果获取方式是下载url：填写文件的下载路径 |      |
| 绑定通讯串口 | 使用那个串口下载固件                                         |      |
| 每包长度     | 每一个下载包的长度。防止设备串口数据超过接受能力内存和串口传送，都会决定文件可能一次性下载，必须分包后慢慢下载 |      |
| 每包间隔     | 一个包与一个包之间的最小间隔。防止设备串口数据超过接受能力实际上由于网络延迟理论是大于这个时间的 |      |
| 数据识别码   | 无:表示数据纯透传，不做任何标记数据识别码：每一个包有固定格式，"UPFILE:"+"文件总长度:"+"当前长度:"+"本报包长度:"+数据。方便用户解析数据前4个字段格式都是字符串的使用:间隔 |      |
