本文描述银尔达透传协议。本协议服务器只记录设备上报的原始数据，不做任何解析。使用场景是IOT平台作为硬件连接服务器，把数据转发到客户的业务服务器上面处理，客户的业务服务器通过API 发送数据给设备。

本协议产品还支持平台发送设备需要的任何数据给设备，实现在web平台上控制任意设备。

不协议产品不支持小程序绑定，自支持IOT平台控制或者API对接查询控制。

注意目前IOT平台协议支持了，但是IOT平台API还不支持，功能受限。



# 一、约定

设备使用MQTT协议与服务器进行通讯

MQTT支持3.1.1版本。

MQTT协议的客户端ID，用户，密码在创建产品，添加设备后获取。

MQTT QOS只支持0，清楚会话为1，topic 不做持久保存。

透传的数据如果是中文，只UTF-8 可以正常显示

注意创建的产品密码要妥善保管。

# 二、设备管理说明

2.1、设备连接

服务器通过MQTT三要素进行识别合法设备连接，如果不合法服务器需要拒绝连接。

MQTT三要素是客户端ID，用户和密码，在创建产品的时候就已经确认了。其中密码是后期可以修改的，一修改全部设备都同时修改。

2.2、设备激活

只要设备授权了，并且与服务器有通讯，设备就算激活。

2.3、设备在线

 MQTT连接上后在线

2.4 、设备离线

 MQTT断开离线。

 MQTT连接中，但是5分钟没收到任何交互数据，表示离线，并且服务器主动断开MQTT连接。

2.5、重发机制

透传协议，服务器不做任何重复机制，用户自己保证数据的到达和重发逻辑，比如可以发送数据，业务服务器收到后做应答来实现。



# 三、系统保留数据点

系统保留数据点，就是系统默认已经创建了一些必要的字段，用户不需要再重新创建，可以直接使用上传。如果这些字段的功能不满足你需求，可以重新创建其他名字的字段替代。

| 表示ID | 显示名称 | 类型   | 读写 | 作用                                                         |
| ------ | -------- | ------ | ---- | ------------------------------------------------------------ |
| imei   | IMEI     | 字符串 | 只读 | 设备的IMEI编码，一般是4G模块有，唯一属性支持IMEI编码的设备才上报，建议注册包上报一次设备详情里面显示 |
| mac    | MAC      | 字符串 | 只读 | 设备的MAC地址支持MAC地址的设备才上报，建议注册包上报一次设备详情里面显示 |
| iccid  | ICCID    | 字符串 | 只读 | SIM卡ICCID，可以用来管理SIM卡，查询SIM卡流量等，基本是必要的建议注册包上报一次设备详情里面显示 |
| imsi   | IMSI     | 字符串 | 只读 | SIM卡IMSI，可以用来管理SIM卡，查询SIM卡的归属运营商等建议注册包上报一次设备详情里面显示 |
| pver   | 硬件版本 | 字符串 | 只读 | 建议注册包上报一次设备详情里面显示                           |
| fver   | 固件版本 | 字符串 | 只读 | 建议注册包上报一次设备详情里面显示                           |



# 四、注册包命令-reg

设备连接服务器的时候发送，重新连接服务器的时候第一个发送的数据包。这些数据点是系统默认给设备添加的，用户不需要去手动添加。注册包一般上传IMEI，ICCID，版本号这些用于管理设备的基础信息使用。



| 功能     | 字段                                                         | 类型   | 必须 | 值说明                         |
| -------- | ------------------------------------------------------------ | ------ | ---- | ------------------------------ |
| 功能字段 | cmd                                                          | 字符串 | 是   | “dreg”，固定                   |
| 消息ID   | did                                                          | 字符串 | 是   |                                |
| ICCID    | iccid                                                        | 字符串 | 否   | SIM 卡ICCID，用来查询SIM卡信息 |
| IMSI     | imsi                                                         | 字符串 | 否   | SIM 卡IMSI，用来查询SIM卡信息  |
| 硬件版本 | pver                                                         | 字符串 | 否   |                                |
| 固件版本 | fver                                                         | 字符串 | 否   |                                |
| 时间戳   | times                                                        | 字符串 | 否   | 时间戳ms                       |
|          |                                                              |        |      |                                |
| 实例     | {“cmd”：“dreg”,“did”：“1”,“iccid”：“1234567891234567890000”，“fver”:”DTU_1.1.1”} |        |      |                                |

服务器应答

| 功能     | 字段                          | 类型   | 必须 | 值说明                 |
| -------- | ----------------------------- | ------ | ---- | ---------------------- |
| 功能字段 | cmd                           | 字符串 | 是   | “dregbck”，固定        |
| 消息ID   | did                           | 字符串 | 是   | 与设备上报的消息ID相同 |
| 实例     | {“cmd”：“regbck”，“did”：”1”} |        |      |                        |



# 五、透传命令

设备除了发送注册包以外，其他数据都是透传数据。服务器不做数据处理，直接透传到目标的业务服务器。

发送的数据可以是JSON，可以字符串，可以是HEX等任意数据。

服务器会记录收到数据的时间和数据



注意：

数据里面如果是JSON，不能带" cmd”：“dreg”字段，防止服务器认为是注册包，解析错误。

每一包保证自己的包不要粘连，防止串口的多个包粘连到MQTT协议一个包发送出了，自己的业务服务器解析失败。
